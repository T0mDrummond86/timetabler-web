**The same class appearing twice** in the Classes list, once for each
qualification that teaches it, is what this fixes. *ICTNWK540* might run in both
a Certificate IV and a Diploma; if each course study plan was imported on its
own, it arrives as **two separate classes** with slightly different names.
**Consolidate** folds those duplicates into one class linked to every
qualification that teaches it.

## Marking them

On the **Classes** tab each class has a tick beside it. **Tick the class you
want to find the duplicates of first** — everything else is measured against it.

Two helpers sit above the list:

- **Suggested** ticks every class that delivers all of the same units as the
  first class you ticked. A suggestion may deliver *more* — the same class run
  under a Diploma often bundles an extra unit — but it must cover all of them,
  so a class delivering only some is left alone. It is a starting point, not a
  verdict: two classes can legitimately deliver the same units, so read the list
  before consolidating.
- The filter above it narrows the list to **Marked common**, or to **Like <the
  first ticked class>** — the suggestions — which is how you work through a
  large session.

Both need a class ticked first. If the class you tick has no unit codes there is
nothing to match on, and the button says so rather than ticking everything —
fill its **Units** in first, or tick the duplicates by hand.

**Clear marks** unticks everything and starts again from a new first class.
Marks are saved as you tick them, so you can mark a session over several
sittings.

## Consolidating them

With two or more ticked, press **Consolidate…**. The dialog asks the only
question that matters: **which class stays**. Everything else follows from it.

The class you keep:

- gains every **qualification** the others were linked to,
- gains every **group** that delivered them,
- receives all their **placecards**, wherever they sit on the grid,
- keeps **its own** name, duration, double-session setting and colour.

The classes folded in are **deleted**.

Leave **carry the unit codes over** ticked unless the surviving class genuinely
does not deliver them — otherwise those codes disappear from the timetable and
from the admin export.

## What is not carried across

Settings belong to the class you keep, so anything set only on a folded class
goes with it: its **allowed rooms**, its **allowed lecturers**, its online
student counts and its LAPs. The dialog counts these before you commit.

## Afterwards

Moving placecards onto one class can leave two of them on the same group at the
same time. That is an ordinary clash, and the result line says how many were
created so you can go and resolve them.

Consolidation cannot be undone from inside the app. It only ever runs on the
classes you have ticked, and only within one session.

To avoid the problem in the first place, use
[Duplicate](#quals-duplicate) when you need the same qualification twice —
it shares classes instead of recreating them.
